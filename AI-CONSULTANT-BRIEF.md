# ИИ-консультант: краткий план

Общий обзор для владельца. Работа идёт в двух проектах, у каждого свой план. Модель, которая работает над проектом, читает только его план и общий раздел «Контракт между проектами».

## Файлы и кто с чем работает

| Файл | Где живёт | Для кого |
|---|---|---|
| `AI-CONSULTANT-BRIEF.md` (этот) | `pearls-migrator/` | владелец, общий обзор |
| `AI-CONSULTANT.md` | `pearls-migrator/`, копия в `amasters-ai/` | идея, правила корпуса, интерфейс (общая для обоих) |
| `AI-CONSULTANT-PLAN-PEARLS-MIGRATOR.md` | `pearls-migrator/` | модель №1: проект `pearls-migrator` (ноутбук и Москва) |
| `AI-CONSULTANT-ROADMAP-AMASTERS-AI.md` | положить в `amster/amasters-ai/` (переименовать, например, в `ROADMAP.md`) | модель №2: новый проект `amasters-ai` (Амстердам) |

Модели не мешают друг другу, потому что:

- у каждой свои папка, репозиторий и план;
- единственная связь между ними — раздел «Контракт между проектами» (адрес абзаца, формат экспорта корпуса, набор `consultant-kit/`). Он одинаков в обоих планах, источник правды — `pearls-migrator`;
- модель №2 не читает код `pearls-migrator`: всё нужное ей приезжает в `consultant-kit/` (копии исходников, фикстуры, образец корпуса), который вы переносите вручную в `amasters-ai/vendor/pearls-migrator/`;
- если одной модели нужно изменить контракт, она не правит чужой проект, а записывает изменение в раздел контракта своего плана и сообщает вам; вы передаёте это второй модели.

## Что это

`ai.amasters.ru` — отдельный сайт на Амстердаме. Посетитель задаёт вопрос по учению и получает три вещи:

- найденные абзацы дословно, с автором, типом, названием и датой;
- ссылки на конкретный абзац на `amasters.ru`;
- короткий ответ ИИ по этим абзацам, пока не исчерпан дневной лимит. После лимита остаются только абзацы.

Консультант работает как библиотекарь корпуса: пересказывает только найденное. Ответ от лица Владыки он не пишет, новых призывов и мантр не сочиняет, личных советов не даёт.

## Откуда берутся данные

Два вида источников.

1. **Основной корпус** — 252 выпуска, около 35 тысяч абзацев.
   - Раз в квартал вы добавляете выпуск на ноутбуке и деплоите сайт. Последним шагом `npm run corpus:push` собирает экспорт из `data/parsed/`, отправляет его на Амстердам и запускает `ingest`.
   - Номера абзацев считаются тем же `toBody`, что строит страницу выпуска. Это даёт якоря `amasters.ru/pearls/{год}/{slug}#d{d}-p{p}`. Единственная правка Москвы — `id` на каждом абзаце страницы.
   - Затем `check:links` сверяет базу консультанта с публичными страницами.
2. **Дополнительный корпус** — неопубликованные материалы без ссылок.
   - Вы кладёте файлы в локальную папку и запускаете `extra:push`. Команда копирует их через `rsync` в приёмник на Амстердаме, дальше ноутбук не нужен.
   - Отдельный воркер `amasters-ai-worker` берёт файлы из очереди в Postgres, по два одновременно. Стадии: разбор текста, метаданные, абзацы, проверка совпадений, эмбеддинги.
   - Метаданные определяет та же система, что у основного корпуса: схема, промпт и нормализация из `pearls-migrator`. Если автор не определён, документ ждёт подтверждения (`needs_review`) и в поиск не попадает.
   - **Основной корпус главнее.** Абзацы, совпавшие с основным, не показываются и не ищутся. Остальные абзацы остаются. Документ, совпавший целиком, помечается дублем. Совпадение пересчитывается после каждой загрузки основного корпуса.
   - Дополнительные материалы показываются отдельным блоком без ссылок и без «Контекста». В ИИ-ответ они не попадают. Для эмбеддингов и метаданных их можно отправлять в OpenAI.

## Как отвечает сервис

Запрос `POST /api/ask` идёт по шагам:

1. Лимиты и фильтры.
2. Шаблоны отказа без модели: «продиктуй», личные, медицинские и юридические советы.
3. Поиск: полнотекст `russian` со словарём синонимов и точной фразой (чтобы находилось «Я ЕСМЬ»), плюс векторы, если замер покажет, что они нужны.
4. Порог слабости. Если опоры нет, модель не вызывается, показываются «ближайшие места».
5. Отбор абзацев, склейка дублей.
6. Вызов модели, если лимиты позволяют. Она получает только отобранные опубликованные абзацы и возвращает блоки со списком `paragraphIds`. Цитаты и подписи подставляет код.
7. Проверки кодом: id реальные, нет формы веления («Возлюбленные…», «Я повелеваю…»). Формула «Я ЕСМЬ» допустима.
8. При любой ошибке всё равно приходят абзацы.

Каталожные вопросы («какие диктовки автора есть») целиком собирает код, без модели.

## Данные об авторах

Один «Геркулес» (алиасы сводятся к `gerkules`), имени «Геракл» нет. «Элохим», «Архангел», «Элементал» — ранг, он хранится отдельным полем `author_rank`, а не частью имени.

## Лимиты

- 20 ответов ИИ в день на посетителя (подписанная cookie), потолок по IP, суточный потолок сайта и месячный лимит проекта OpenAI.
- `limit_req` в nginx и выключатель `CONSULTANT_AI_ENABLED`.
- В журнале нет текста вопросов.

## Стек

- Express 5, React и Vite, PostgreSQL 18, Node `v24.22.1`, PM2.
- Два процесса PM2: сайт и воркер.
- `openai` напрямую из Амстердама, `noindex`.
- Москва от консультанта не зависит, запасного переноса на неё нет.

## Порядок работ и зависимости

| Проект | Этапы | Срок |
|---|---|---|
| `pearls-migrator` | M1 контракт, экспорт, `consultant-kit` → M2 якоря абзацев на странице → M3 отправка на Амстердам и релизный порядок | 4–6 дней |
| `amasters-ai` | A0 подготовка → A1 каркас и инфраструктура → A2 приём корпуса и поиск без ИИ → A3 векторы (по замеру) → A4 ответ ИИ → A5 эксплуатация и закрытый прогон → A6 воркер дополнительных материалов | около 4 недель без A6, A6 ещё 4–5 дней |

Что чего ждёт:

- A1–A2 стартуют, как только готов M1 (образец и полный экспорт корпуса лежат в `consultant-kit/`). Боевой Амстердам для разработки не нужен.
- `check:links` и запуск (A5) требуют M2 на проде.
- Полный путь «ноутбук → Амстердам» проверяется, когда готовы M3 и `ingest` из A2.
