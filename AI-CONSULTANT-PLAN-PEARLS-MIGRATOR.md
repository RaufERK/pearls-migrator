# ИИ-консультант: план для `pearls-migrator`

Этот файл читает модель, которая работает в проекте `pearls-migrator`. Новый проект `amasters-ai` (сервис консультанта на Амстердаме) ведёт другая модель по своей дорожной карте. Общий обзор — `AI-CONSULTANT-BRIEF.md`, идея и правила корпуса — `AI-CONSULTANT.md`. Править файлы `amasters-ai` отсюда не нужно и нельзя.

**Что делает этот проект для консультанта:** отдаёт ему корпус и контракт. Сам консультант (поиск, ответы ИИ, лимиты, воркер дополнительных материалов) здесь не строится.

Корпус для сверки чисел: 252 выпуска, 321 документ, 34 796 абзацев, 260 строк-разделителей, пустых абзацев нет.

Правила проекта (`.cursor/rules/project.mdc`) действуют как обычно: ESM, строгий TypeScript, Zod на границах, тесты `node:test`, порядок каталога только в `src/catalogOrder.ts`, страницы остаются серверными (`force-dynamic`), импорты наверху файла, коммиты и пуши только по просьбе владельца. На Москву уходит только то, что нужно сайту (якоря); всё остальное работает на ноутбуке.

**Решения владельца (24.11.2026), которые касаются этого проекта:**

- Корпус отправляется на Амстердам с ноутбука при квартальном релизе, не ночным дампом Москвы.
- «Я ЕСМЬ» — устойчивое выражение, в экспорте и данных не заменяется.
- «Геркулес» один автор, имени «Геракл» нет нигде. «Элохим», «Архангел», «Элементал» — ранг, а не имя; каноникализацию авторов делает консультант, здесь данные каталога не правятся.
- Москва для консультанта не запасной вариант.

## Контракт между проектами

Источник правды — этот проект. Тот же раздел есть в дорожной карте `amasters-ai`. Менять контракт можно только здесь, затем регенерировать `consultant-kit/` и сообщить владельцу.

### К1. Адрес абзаца

- `d` — `PearlDocument.position` с 1; на странице берётся из поля `position`, не из индекса в JSX.
- `p` — номер абзаца в `toBody(content)` (`src/catalogLabels.ts`) с 1, после разреза по `\n{2,}`. Разделители (`_____`, `***`) в нумерации остаются. Функция номера вызывает `toBody`, второй копии регулярного выражения нет.
- HTML: `id="d{d}-p{p}"`. Ссылка: `https://amasters.ru/pearls/{siteYear}/{slug}#d{d}-p{p}` (`siteYear` — год публикации выпуска).
- Идентификатор абзаца в API консультанта: `pearls:{slug}#d{d}-p{p}`; у дополнительных материалов `extra:{documentId}#p{n}`.

### К2. Формат экспорта корпуса

Версия формата `format: 1`. Два файла с общим временным штампом `<YYYYMMDDTHHMMSSZ>`:

- `corpus-<штамп>.ndjson.gz`: одна строка JSON — один документ (`PearlDocument` вместе с полями выпуска):

  ```json
  {
    "slug": "2026Q2-3",
    "siteYear": 2026,
    "siteMonth": 6,
    "siteLabel": "Июнь 2026",
    "siteSortDate": "2026-06-01",
    "pearlTitle": "Жемчужины Мудрости. Июнь 2026",
    "position": 1,
    "documentTitle": "…",
    "documentType": "dictation",
    "description": "…",
    "authorName": "Господь Майтрейя",
    "authorDisplayName": "Господь Майтрейя",
    "authorSlug": "maitreya",
    "creationDate": "2026-05-01",
    "creationYear": 2026,
    "creationRaw": "…",
    "content": "абзацы, склеенные через \n\n",
    "paragraphsCount": 41
  }
  ```

  `authorDisplayName` строится тем же `normalizeAuthorDisplayName`, что и на сайте. Поля `siteMonth`, `siteLabel`, `documentTitle`, `authorName`, `authorSlug`, `authorDisplayName`, `creationDate`, `creationYear`, `creationRaw` могут быть `null`. `header` и `footer` не экспортируются: футер в поиск не входит. `paragraphsCount` равен `toBody(content).length`. Строки идут в порядке `siteSortDate`, затем `slug`, затем `position`. Схема Zod записи лежит в `src/corpusRecord.ts` и уезжает в набор (К4).
- `corpus-<штамп>.manifest.json`: `{ "format": 1, "createdAt", "file", "sha256", "pearls", "documents", "paragraphs" }`; `sha256` — файла `.ndjson.gz`, `paragraphs` — сумма `paragraphsCount`.

### К3. Доставка

Только с ноутбука владельца: `rsync` файлов в `/home/appuser/apps/amasters-ai/shared/corpus/inbox/` (SSH-алиас `amster_app`), затем `ssh amster_app`, команда загрузки `npm run ingest -- --file corpus-<штамп>.ndjson.gz` в `/home/appuser/apps/amasters-ai/current`. Точная команда подтверждается проектом `amasters-ai` в его Фазе A0 и задаётся здесь переменной окружения. Загрузка идемпотентна: повторная отправка того же содержимого ничего не меняет.

### К4. Набор для консультанта (`consultant-kit/`)

`npm run consultant:kit` собирает папку `consultant-kit/` (в `.gitignore`), которую владелец вручную копирует в `amasters-ai/vendor/pearls-migrator/`:

- `src/`: дословные копии нужных исходников с шапкой «скопировано из pearls-migrator, коммит `<sha>`»: `catalogLabels.ts` (`toBody`, `normalizeAuthorDisplayName`), `paragraphContract.ts`, `corpusRecord.ts`, `metadataAi.ts`, `metadataNormalization.ts`, `types.ts` (нужные типы), `word/extractDocxText.ts`, `pdf/extractPdfLines.ts`, `libreOffice.ts`;
- `fixtures/paragraph-contract.json`: образцы `content` с разделителями, тройными переводами строк и хвостовыми пробелами и ожидаемые абзацы с номерами;
- `fixtures/metadata-contract.json`: SHA-256 от `SYSTEM_PROMPT` и JSON-схема `AiMetadataSchema`;
- `corpus/`: полный экспорт (К2) и маленький образец из 5 выпусков для тестов;
- `README.md`: коммит-источник, дата, список файлов, как обновлять.

Набор пересобирается всякий раз, когда меняются `toBody`, нумерация, `normalizeAuthorDisplayName`, `SYSTEM_PROMPT` или схема метаданных, и владелец копирует его заново.

### К5. Метаданные

Дополнительные материалы консультанта используют ту же систему метаданных (`metadataAi.ts`, `metadataNormalization.ts`), поэтому этот проект отвечает за стабильность её публичной части: имена экспортов, `AiMetadataSchema`, `SYSTEM_PROMPT`, `applyAiMetadata`, `normalizeExistingDocument`. Изменение промпта или схемы = пересборка набора.

## Фазы

### M1. Контракт, экспорт, набор для консультанта (2–3 дня)

Разблокирует вторую модель, поэтому делается первой.

1. Общее преобразование `data/parsed` → строки `Pearl` / `PearlDocument` выносится из `src/cli/seed.ts` в отдельный модуль (например `src/catalogRows.ts`); `seed.ts` использует его. Поведение сида не меняется: проверка по нескольким выпускам, что строки совпадают с прежними.
2. `src/paragraphContract.ts`: номера абзацев, `paragraphId`, `anchorId`, всё через `toBody`. Тесты `node:test` в явный список скрипта `test` в `package.json`, иначе CI их не увидит.
3. `src/corpusRecord.ts` (Zod, К2) и `src/cli/corpusPush.ts`. На этом этапе работает `--dry-run`: собирает `corpus-<штамп>.ndjson.gz` и манифест в `consultant-kit/corpus/`, печатает счётчики, ничего не отправляет. Опция `--sample <n>` собирает образец из `n` выпусков.
4. `npm run consultant:kit` по К4, фикстуры генерируются из реальных данных.
5. Тесты: запись проходит Zod на всех 321 документах; счётчики 252 / 321 / 34 796; `paragraphsCount` равен `toBody(content).length` для каждого документа; нет пустых абзацев; склейка `body` через `\n\n` и `toBody` дают одни и те же абзацы на всех 252 файлах `data/parsed/`.

**Выход:** `lint`, `test`, `build` зелёные; `corpus:push --dry-run` и `consultant:kit` выполняются на полном корпусе; `consultant-kit/` передан владельцу для `amasters-ai`.

### M2. Якоря абзацев на странице выпуска (1–2 дня, параллельно)

Единственное изменение Москвы, выкатывается `npm run deploy:code`. Сид не запускается и каталог не перезаливается.

1. `position` добавляется в данные страницы выпуска (`toPearlDetail`).
2. `id` на каждом `<p>` тела (формат К1, через `paragraphContract`), `scroll-mt-28` на всех размерах (шапка `sticky` и на телефоне), подсветка `:target` в `web/app/globals.css`. Без скрипта.
3. `src/cli/smoke.ts` проверяет `id="d1-p1"` в HTML выпуска.
4. Контрактный тест (по строке `content`, как она лежит в базе) входит в `npm test` и CI.

**Выход:** `lint`, `test`, `build`, `build:web` зелёные локально и в CI; после деплоя `smoke` проходит, `https://amasters.ru/pearls/2026/2026Q2-3#d1-p3` прокручивает и подсвечивает абзац ниже шапки на десктопе и на 375 px (проверено в браузере); `sitemap.xml` и HTML главной не изменились.

### M3. Отправка на Амстердам и порядок релиза (1 день, когда в `amasters-ai` готов `ingest`)

1. `corpus:push` без `--dry-run`: `rsync` и запуск `ingest` по К3, настройки хоста и путей в `.env` (в `.gitignore` уже есть). Остановка с понятной ошибкой, если `ingest` вернул отказ. Единственный источник данных — `data/parsed/`, база не читается.
2. Полный прогон на реальном Амстердаме, повторная отправка того же корпуса даёт «без изменений».
3. `WORK-FLOW.md`: порядок релиза квартала — сид и сборка → `npm run deploy` → `npm run corpus:push` → в проекте `amasters-ai` `npm run check:links` → при включённых векторах `npm run embed`. Отдельной строкой: после изменения `toBody`, нумерации, `normalizeAuthorDisplayName`, `SYSTEM_PROMPT` или схемы метаданных пересобрать `consultant-kit/` и передать в `amasters-ai`.
4. `README.md`: два предложения про консультанта и ссылка на этот план.

**Выход:** полный путь «ноутбук → Амстердам» проходит; шаг релиза записан в `WORK-FLOW.md`.

### Отдельно: правка квартального релиза (не в релиз с якорями)

`seed.ts` сейчас делает `deleteMany` вне транзакции и затем пишет выпуск за выпуском: обрыв посреди сида оставляет пустой или частичный каталог. Перезаливка должна идти в одной `prisma.$transaction` с таймаутом 120 с. Замерить время замка таблиц на полном корпусе, проверить откат вручную (ошибка посреди заливки оставляет прежние данные). Правится в ближайший квартальный релиз, не вместе с якорями.

### После запуска консультанта (решения владельца, не сейчас)

- Ссылка на `ai.amasters.ru` в шапке `amasters.ru` — отдельным решением после окна проверки.
- Правка имён и slug авторов в самих данных каталога (`gerkules` / `elohim-gerkules` / `hercules` и др.) — необязательный отдельный релиз; до него консультант справляется своей таблицей алиасов.

## Риски этого проекта

| Риск | Что делаем |
|---|---|
| Ссылка попала не на тот абзац | Одна функция адреса, `paragraphContract.ts`, контрактный тест по 252 файлам, `paragraphsCount` в экспорте, `check:links` на стороне консультанта |
| Текст на `amasters.ru` изменился, нумерация сдвинулась | После релиза `corpus:push`, затем `check:links`; ссылки с якорем не вечные |
| `toBody`, промпт метаданных или нормализация изменились, а копии в `amasters-ai` старые | Фикстуры и тесты копий в `amasters-ai`; правило пересобрать `consultant-kit/` записано в `WORK-FLOW.md` |
| Обрыв сида оставляет каталог пустым | Транзакция при ближайшем релизе (раздел «Отдельно») |
| Корпус отправлен, но загрузка не прошла | `corpus:push` показывает ответ `ingest`; повторная отправка безопасна |
