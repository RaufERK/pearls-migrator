# План: ИИ-консультант на `ai.amasters.ru` (версия 4)

Рабочий план. Опирается на `AI-CONSULTANT.md` и версию 3. Версия 3 не менялась.

Корпус, по которому сверены числа: 252 выпуска, 321 внутренний документ, 34 796 абзацев тела, 260 строк-разделителей, пустых абзацев нет.

## Что изменено относительно версии 3

1. Серапис Бей не склеивается со slug Марка Л. Профета. Чинится один документ с чужим slug. У остальных пар назван канонический slug, старый адрес фильтра на `amasters.ru` продолжает открывать того же автора.
2. Карточка соседних абзацев по-прежнему одна на выпуск, но ссылка и подсветка остаются у каждого абзаца.
3. Суточный слот списывается только за ответ, который разобрался по схеме. Ошибка прокси слот возвращает. Процесс консультанта один.
4. Ожидаемый абзац в золотом наборе отмечает человек. Поиск лишь помогает открыть выпуск.
5. Поиск первой рабочей версии — словарь синонимов и полнотекст по ИЛИ. Кворум и эмбеддинги включаются только по замеру. Размерность вектора выбирается сравнением полноты, а не заранее.
6. Контракт абзаца живёт в `pearls-migrator`. У полной перезаливки базы явный таймаут транзакции.

## 1. Контракт данных и адресов

### 1.1. Адрес абзаца

- `d` — `PearlDocument.position`, целое с 1. На странице выпуска берётся из поля `position`, не из индекса массива в JSX.
- `p` — номер абзаца в массиве `toBody(content)` из `src/catalogLabels.ts`, целое с 1, после разреза по `\n{2,}` и отбрасывания пустых строк. Строки-разделители (`_____`, `***`) из нумерации не выбрасываются: счёт на `amasters.ru` и в консультанте совпадает.
- HTML-атрибут на странице выпуска: `id="d{d}-p{p}"` (например, `d1-p15`).
- Сквозной идентификатор (`paragraphRef`): `{slug}#d{d}-p{p}` (например, `2014Q2-1#d1-p15`). Им пользуются API, промпт, `paragraphIds[]` и золотой набор.
- Полная ссылка: `https://amasters.ru/pearls/{siteYear}/{slug}#d{d}-p{p}`. `siteYear` — год публикации выпуска на сайте, не год создания.
- Футер адресов не имеет и в индекс не входит. Место и дату создания показывают метаданные карточки.
- Подряд идущие абзацы одного документа показываются одной карточкой выпуска. У каждого абзаца внутри карточки своя ссылка на свой `id`. Один хеш не подсвечивает диапазон, скрипт на страницу выпуска для этого не добавляется.
- Модуль `src/paragraphContract.ts` (`toBodyParagraphs`, `formatParagraphAnchor`, `formatParagraphRef`, `parseParagraphRef`) живёт в `pearls-migrator` и покрыт тестами. В `amasters-ai` лежит копия. Общая JSON-фикстура тест-векторов хранится в `pearls-migrator`; тест копии падает, если результаты разошлись.

### 1.2. Схема БД консультанта (`amasters_ai`, PostgreSQL 16)

Драйвер `pg`, миграции плоскими SQL-файлами в `db/` (как в `amasters_info`).

- `document`:
  - первичный ключ `(slug, position)`;
  - `site_year INT NOT NULL`, `site_sort_date TEXT NOT NULL`, `site_label TEXT`;
  - `document_type TEXT NOT NULL`, `document_title TEXT`;
  - `author_name TEXT`, `author_slug TEXT` (канонические значения);
  - `creation_date DATE`, `creation_year INT`, `creation_raw TEXT`;
  - `pearl_raw TEXT`, `description TEXT NOT NULL`;
  - `header_tsv TSVECTOR` (вес `A` — автор, вес `B` — название; GIN-индекс).
- `paragraph`:
  - `ref TEXT PRIMARY KEY` (`{slug}#d{position}-p{paragraph_number}`);
  - `FOREIGN KEY (slug, position) REFERENCES document ON DELETE CASCADE`;
  - `paragraph_number INT NOT NULL`, `UNIQUE (slug, position, paragraph_number)`;
  - `text TEXT NOT NULL`;
  - `is_separator BOOLEAN NOT NULL DEFAULT FALSE` для строк `^[_*\-=~\s]+$`;
  - `text_hash TEXT NOT NULL` — SHA-256 нормализованного текста абзаца (`ё → е`, схлопнутые пробелы, нижний регистр);
  - `window_hash TEXT NOT NULL` — SHA-256 окна `prev + "\n\n" + curr + "\n\n" + next`, где соседи — ближайшие абзацы того же документа с `is_separator = FALSE`;
  - `body_tsv TSVECTOR` (конфигурация `russian`, нормализация `ё → е`; пустой у разделителей; GIN-индекс).
- `embedding` (создаётся в Фазе 3, без внешнего ключа на `paragraph`, чтобы пережить пересборку корпуса):
  - первичный ключ `(model, dims, window_hash)`;
  - `vector BYTEA NOT NULL` (`Float32Array`, little-endian, L2-нормированный), `created_at TIMESTAMPTZ`.
- `usage_day`:
  - `day DATE PRIMARY KEY` (календарная дата `Europe/Moscow`);
  - `ai_calls INT NOT NULL DEFAULT 0`, `input_tokens BIGINT NOT NULL DEFAULT 0`, `output_tokens BIGINT NOT NULL DEFAULT 0`.
- `request_log`:
  - `id BIGSERIAL PRIMARY KEY`, `created_at`, `route_kind` (`answer` | `catalog_list` | `search_only` | `refused`), `ai_status` (`ok` | `disabled` | `budget_exceeded` | `busy` | `weak_evidence` | `refused` | `error`), `refusal_reason`, `paragraphs_count`, `latency_ms`, `input_tokens`, `output_tokens`. Текст вопроса и IP не хранятся.

### 1.3. Поток `POST /api/ask`

Вход (Zod): `{ question: string (3..500 знаков), authorSlug?: string, documentType?: DocumentType }`.

1. Барьеры: длина, фильтры, лимит запросов на IP (`trust proxy = 'loopback'`).
2. Классификация без модели, узкими шаблонами:
   - личное руководство, медицинский или бытовой совет, просьба продиктовать или дать призыв «от имени» Владыки → отказ (`personal_guidance` | `request_for_dictation`) без модели и без подборки абзацев;
   - каталожный вопрос («какие диктовки или лекции автора есть») → список документов (`catalog_list`) со ссылкой на первый абзац, у которого `is_separator = false`, и с полем `description`. Если документов не больше 10 и ИИ включён, добавляется короткая сводка по названиям и первым содержательным абзацам;
   - остальные вопросы идут в поиск. Вопрос «что Майтрейя говорит о …» — это поиск с фильтром автора, не каталожный список.
3. Поиск (`is_separator = FALSE`):
   - нормализация `ё → е`, стоп-слова, ручной словарь синонимов имён и терминов;
   - полнотекст: значимые слова через ИЛИ, усиление точной фразы и совпадения в `header_tsv`, затем фильтры автора и типа;
   - кворум («не меньше двух групп синонимов») добавляется только если на стартовых 15 вопросах такая выдача пустая или забита шумом;
   - с Фазы 3 к этому рангу добавляется косинус по векторам в памяти (RRF), если Фаза 3 включена.
4. Отбор:
   - одинаковый `text_hash` склеивается: основным остаётся самый свежий по `site_sort_date`, остальные попадают в `alsoIn[]` (`ref`, `url`, `author`, `siteLabel`) и видны в карточке без второго запроса;
   - не больше 3 абзацев с одного внутреннего документа, всего до 8.
5. Если ни один абзац не прошёл порог, модель не вызывается (`weak_evidence`). Слабые кандидаты возвращаются с пометкой «прямого ответа в каталоге не найдено, ближайшие места».
6. Вызов модели при `CONSULTANT_AI_ENABLED=true`:
   - не больше 3 одновременных вызовов в одном процессе;
   - слот `usage_day` резервируется атомарно (`WHERE ai_calls < DAILY_AI_CALL_LIMIT`, старт `100`) до вызова и возвращается, если ответ не разобрался по схеме: таймаут, ошибка прокси, битый JSON, провал проверок. Отказ модели по существу (`refused`) — состоявшийся вызов, слот остаётся списанным;
   - `openai.responses.parse` (`maxRetries: 0`, таймаут 15 с, `temperature: 0`) через `spoken-word.info/openai-proxy/v1`, тем же способом, что уже вызывает `src/metadataAi.ts`;
   - на вход только отобранные абзацы: `{ id, author, documentType, documentTitle, creationDate, sitePublication, text, contextBefore, contextAfter, alsoIn }`. Соседи помечены как контекст;
   - схема Zod: `status: 'answered' | 'refused'`, `refusalReason`, `blocks: Array<{ text, paragraphIds }>` (1..5 блоков). Цитаты и подписи авторов модель не пишет.
7. Проверка кодом до показа:
   - у каждого блока есть хотя бы один `paragraphId`, и каждый id был в кандидатах этого запроса;
   - длина блока и всего ответа в пределах;
   - нет речи от первого лица Владыки вне кавычек;
   - подпись авторов и типов кода собирает по `paragraphIds`; текст карточки и ссылка берутся из базы.
8. Таймаут, ошибка прокси, невалидная схема или провал проверки дают HTTP 200: карточки абзацев и `aiStatus: 'error'` («ИИ-сводка временно недоступна, показаны найденные абзацы»).

Одного вопроса достаточно для одного ответа. История диалога не хранится и в следующий запрос не подмешивается.

Старый `/?authorSlug=gospod-maytreyya` открывает того же автора, что и `maitreya`.

### Фаза 2. Сервис `amasters-ai`: синхронизация и поиск без ИИ (4–5 дней)

В конце фазы справочник абзацев уже публичный, `CONSULTANT_AI_ENABLED=false`, бюджет OpenAI не тратится.

1. Репозиторий `moscow/amasters-ai/`: Express 5, React/Vite, строгий TypeScript, ESM, `lint`, `test` (`tsx --test`), `build`, `/api/health` с `SELECT 1` и таймаутом 3 с.
2. Инфраструктура Москвы по `moscow/AGENTS.md`:
   - база и роль `amasters_ai`, лимит соединений, `REVOKE` сразу после `CREATE DATABASE`;
   - роль `amasters_ai_reader` и `PEARLS_DATABASE_URL` в `shared/.env`; `DATABASE_URL` указывает только на `amasters_ai`;
   - DNS, vhost nginx (`X-Forwarded-For $remote_addr`, `limit_req`, TLS через certbot), `ecosystem.config.cjs` с абсолютным Node `v24.22.1` и `instances: 1`.
3. `npm run sync`:
   - чтение источника в транзакции `REPEATABLE READ READ ONLY`, строки через Zod;
   - отказ от перезаписи, если в источнике меньше 250 выпусков или меньше 300 документов. Сейчас их 252 и 321: порог ловит пустой или оборванный источник и не поднимается вслед за новым годом корпуса;
   - канонические slug, `toBodyParagraphs`, `is_separator`, хэши, `tsvector`;
   - запись в `amasters_ai` одной транзакцией.
4. Поиск из раздела 1.3, режим `catalog_list`, словарь синонимов, склейка дублей, отбор 3/8, порог `weak_evidence`.
5. Страница: вопрос, фильтры автора и типа (`GET /api/filters`), карточки по выпускам, у каждого абзаца ссылка «Читать в выпуске», раскрытие «Контекст» и «Есть ещё в N выпусках», дисклеймер, `noindex`, `robots.txt`.
6. `npm run check:links`: для каждого абзаца базы консультанта на `http://127.0.0.1:3021/pearls/{siteYear}/{slug}` есть `<p id="d{d}-p{p}">` с тем же нормализованным текстом.
7. Золотой набор 40–60 вопросов. Ожидаемый абзац или признак «ответа нет» ставит человек по тексту выпуска. Поиск можно использовать, чтобы открыть кандидата, и нельзя использовать, чтобы решить, что вопрос отвечаемый. В наборе есть группы «вне корпуса», «продиктуй», «посоветуй лично», сравнение авторов и каталожный вопрос. Команда `npm run eval:search` считает попадание точного `paragraphRef` в топ-8.

**Выход:** `check:links` без расхождений на всех абзацах 252 выпусков. `eval:search`: `recall@8 >= 0,70` на отвечаемых вопросах, `weak_evidence >= 0,90` на вопросах вне корпуса. Вопрос про диктовки Господа Майтрейи возвращает все 5. Кворум в этот критерий не входит, пока замер на 15 вопросах его не потребовал.

### Фаза 3. Смысловой поиск (2 дня, только если Фаза 2 не добрала полноту)

Запускается, если перефразированные вопросы не дотягивают до нужной полноты или принято решение довести `recall@8` до `>= 0,85`.

1. На стартовых вопросах сравнить `text-embedding-3-small` при `dimensions: 512` и при `1536`. Цена одинаковая. Буфер на корпус: около 71 МБ и около 210 МБ. Оставить размерность, которая лучше по полноте; при равенстве оставить 512.
2. `npm run embed` дописывает недостающие векторы по `window_hash` для абзацев с `is_separator = FALSE`. Вектор относится к центральному абзацу окна. Команда идемпотентна и продолжается после обрыва.
3. При старте и после `embed` векторы загружаются в один `Float32Array` вместе с массивом `paragraphRef` той же длины. Пустая таблица или недоступный эмбеддинг вопроса оставляют поиск на полнотексте.
4. RRF полнотекста и косинуса, фильтры автора и типа сохраняются, порог `weak_evidence` калибруется по золотому набору.

**Выход:** `recall@8 >= 0,85` на отвечаемых вопросах, `weak_evidence >= 0,90` на вопросах вне корпуса, векторный проход меньше 25 мс, при выключенном прокси поиск остаётся на полнотексте, RSS процесса под нагрузкой меньше 300 МБ на выбранной размерности.

### Фаза 4. Ответ ИИ (3–4 дня)

1. `openai.responses.parse` и Zod-схема из раздела 1.3.
2. Промпт библиотекаря корпуса. Абзацы передаются в отделённом блоке данных. Запрещены речь от первого лица Владыки, новые веления и мантры, личные советы и факты вне переданных абзацев. Разные авторы и типы излагаются раздельно, код ставит им подписи.
3. Проверки раздела 1.3 и деградация до карточек при любой ошибке.
4. Модульные тесты на поддельных ответах: чужой `ref`, пустой `paragraphIds`, «Я, Эль Мория…», слишком длинный текст, битый JSON, таймаут, возврат суточного слота после ошибки и сохранение слота после `refused`.
5. `npm run eval:answer` отдельно от `npm test`: JSON-отчёт по золотому набору для ручной вычитки. Команда платная и недетерминированная.

**Выход:** в отчёт не попадает ни один `paragraphId` вне выданных кандидатов. На группах «вне корпуса», «продиктуй» и «посоветуй лично», включая 10 обходных формулировок, отказ 100%. По ручной проверке не меньше 90% отвечаемых вопросов пересказаны по приведённым абзацам, без внешних знаний модели. При выключенном прокси страница быстрее чем за секунду показывает абзацы и плашку.

### Фаза 5. Эксплуатация до открытия ИИ (2 дня)

1. Защита расходов: `limit_req` и `X-Forwarded-For $remote_addr` в nginx; `trust proxy = 'loopback'`; лимит на IP; семафор на 3 вызова; `usage_day` по Москве со стартовым потолком 100 в `shared/.env`; выключатель `CONSULTANT_AI_ENABLED`; `maxRetries: 0` и таймаут 15 с.
2. `request_log` без текста вопроса и без IP. Logrotate `/etc/logrotate.d/amasters-ai`: `weekly`, `rotate 8`, `compress`, `copytruncate`.
3. Таймер `amasters-ai-sync.timer` в 02:45 по Москве: `sync`, затем `embed`, если Фаза 3 включена, затем `check:links`. К дампу в 03:30 корпус уже в базе. `pearls-migrator` от этого таймера не зависит.
4. Бэкапы и сторож: проект `amasters_ai` в `backup-projects.conf` и в пин-тесте; `amasters-ai` в `pm2` и `auditNpm` на Москве; `https://ai.amasters.ru/api/health` у сторожа в Амстердаме. Подтянуть репозиторий сторожа на обоих серверах и поставить скрипты.
5. В `moscow/AGENTS.md` и `DB-BACKUPS.md` записать порт, vhost, базу, процесс PM2 и исключение для `amasters_ai_reader`.

**Выход:** выключатель мгновенно оставляет поиск без обращений к прокси. Из 10 одновременных запросов при остатке лимита 2 в модель проходят 2, остальные 8 получают абзацы и `budget_exceeded`. Блокировка одного IP не блокирует другой. Ручной цикл дампа, отправки в Амстердам и проверки там заканчивается `DONE status=0` для шести московских баз, учебное восстановление `amasters_ai` в scratch-базу проходит без `pgvector`, сухой прогон сторожа зелёный на обоих серверах. В логах нет текстов вопросов и токенов.

### Фаза 6. Закрытый прогон и запуск (2 дня работы и окно вычитки)

1. На 5–7 дней закрыть `ai.amasters.ru` Basic Auth в nginx. Человек, знающий материалы, задаёт вопросы и сверяет пересказ и ссылки с выпусками.
2. Поправить словарь, порог и тексты отказов, повторить `eval:search` и `eval:answer`.
3. Снять пароль. Три дня смотреть `usage_day`, долю отказов и ошибок.
4. Ссылку в шапку `amasters.ru` добавлять отдельным решением после этого окна.

**Выход:** за закрытый прогон нет битой ссылки на абзац и нет ответа от лица Владыки или по знаниям вне корпуса. После открытия утренний отчёт бэкапов и дневной отчёт сторожа зелёные, расход укладывается в суточный потолок.

## 4. Сроки

Фаза 0: 1–2 дня, параллельно с Фазой 1. Фаза 1: 1–2 дня. Фаза 2: 4–5 дней. Фаза 3: 2 дня, только по результатам Фазы 2. Фаза 4: 3–4 дня. Фаза 5: 2 дня. Фаза 6: 2 дня работы и календарное окно вычитки.

Около 2,5–3,5 недель одним человеком. Фаза 3 в этот срок входит только если полнотекст не добрал полноту.

## 5. Уже принятые решения

1. Корпус читается read-only ролью из `pearls_migrator`. Исключение записывается в `moscow/AGENTS.md`.
2. Чистка авторов входит в Фазу 1 и заодно выравнивает фильтр на `amasters.ru`, со старыми slug как алиасами.
3. Каталожный вопрос возвращает список документов и ссылку на первый содержательный абзац. Краткая сводка модели строится, только если документов не больше 10.
4. Суточный потолок — 100 успешных вызовов модели на весь сайт. Дальше до полуночи по Москве работает поиск абзацев.
5. Диалога нет: один вопрос, один ответ.
6. Перед Фазой 2 нужна A-запись `ai.amasters.ru` и человек, который отмечает ожидаемые абзацы в золотом наборе.
